# 峰谷教练模式

DeepSeek 按北京时间分峰谷计费，高峰价是谷价的两倍：

| | 时间 | 计费 |
|---|---|---|
| 高峰 | 工作日 9:00–12:00、14:00–18:00 | 双倍 |
| 谷时 | 午休 12:00–14:00、18:00 之后、周末全天、法定节假日全天 | 半价 |

这个插件把「什么时候该由 Agent 自己动手」变成一条硬规则。

## 峰时：只拦「没人让它做」的动作

不是「一切动手都停」。判据是这一轮里有没有用户消息：

| 场景 | 峰时行为 |
|---|---|
| 用户说「帮我改这个文件」 | **照做**，该动的文件、该跑的命令、该做的验证一样不少 |
| 没有用户消息，模型自己在往下推（goal 续轮、定时驱动） | 变异类工具被 `ctx.tools.guard()` 拒绝，改成给方案 |
| 用户在别处授权、这一轮没有新消息但要收尾 | 调 `peak_unlock` 解锁 10 分钟 |

实现上靠两个事件夹出来：`agent/inbox/claimed`（用户消息进入本 turn）置位，`agent/turn-stopping`（本 turn 即将关闭）清位。拿不到会话身份时按「有用户指令」处理 —— 误拦用户的活比多放行更糟。

同时往系统提示末尾追加教练指令：别扩大范围、别顺手改别的文件、需要多做一步之前先问。

读类工具（`read`、`glob`、`grep`、网页搜索与抓取）在任何情况下都放行。

## 谷时：完全默认

不拦工具、不插提示。装上之后谷时你感觉不到它存在。

## peak_unlock：把该做完的活推下去

用户这一轮开口要的东西本来就不拦，不需要它。它只用于「用户在别处已经授权、但当前这一轮没有新消息」的收尾场景，解锁默认 10 分钟。

## 配置

| 字段 | 默认 | 说明 |
|---|---|---|
| `enabled` | `true` | 总开关 |
| `peaks` | `['09:00-12:00','14:00-18:00']` | 高峰窗口，北京时间，支持跨零点 |
| `weekendValley` | `true` | 周末全天谷时；关掉会让周末被拦 |
| `holidays` | `[]` | 额外谷价日 `YYYY-MM-DD`，每年自己补次年安排 |
| `blocked` | 18 个工具名 | 峰时且**没有用户指令**时要拦的工具 |
| `unlockedMinutes` | `10` | 解锁时长 |
| `coachText` | 空 | 留空用内置文案 |

默认拦截：`write` `edit` `pwsh` `bash` `shell` `subagent` `subagent_fork` `workflow` `plugin_manager` `purge_apply` `purge_revert` `schedule_create` `schedule_edit` `create_goal` `update_goal` `bili_run` `bili_reply` `pixiv_save`。

## 限制

- 解锁窗口是进程级的，不按会话隔离。同一台机器上多个会话并行时，一处解锁会短暂放行别处。
- 时段判定用本机时钟 + 固定 UTC+8，不看系统时区。机器时间不准，判定就不准。
- 法定节假日清单需要自己维护，插件不联网拉国务院安排。
- 它只改变「这一轮干了多少活」，不改变上游计费。峰时你照样可以解锁硬做，钱照付。
- `@deepseek-ai/schemastery` 解析不到时插件仍会加载，但设置表单不出现，全部走默认值。
