# 峰谷教练模式 · dsh-peak-coach

DeepSeek 的价格按北京时间分峰谷：**高峰价是谷价的两倍**。

| | 时间（北京时间） | 计费 |
|---|---|---|
| 高峰 | 工作日 9:00–12:00、14:00–18:00 | 双倍 |
| 谷时 | 午休 12:00–14:00、18:00 之后、周末全天、法定节假日全天 | 半价 |

在峰时让 Agent 自己大干一场，等于同样的活付两倍的钱。这个插件把「什么时候该动手」变成硬规则。

## 它做什么

**峰时（教练模式开启）**

拦的是「**没人让它做**」的那一轮，不是「一切动手」。

| 场景 | 峰时行为 |
|---|---|
| 你说「帮我改这个文件」 | **照做** —— 该改的文件、该跑的命令、该做的验证，一样不少 |
| 你什么都没说，它在自动往下推（goal 续轮、定时驱动） | 拦住变异类工具，改成给方案 |
| 你在别处授权过、这一轮没有新消息但要收尾 | 调 `peak_unlock` 解锁 10 分钟 |

判据是 `agent/inbox/claimed` 与 `agent/turn-stopping` 夹出来的「这一轮里有没有用户消息」。有，就是你点名的活；没有，就是它自己在加戏。

同时往系统提示插一段教练指令：别扩大范围、别顺手改别的文件、要多做一步之前先问你，而不是替你决定。

**读文件、搜索、查文档在任何情况下都放行**，所以建议有依据，不是空口猜。

**谷时**

什么都不做。不拦工具、不插提示，完全是默认模式。

## 装

```bash
dsh plugin add dsh-peak-coach
```

或者插件页 → 添加插件 → 填本地目录 / npm 包名。

装完刷新即可，不用重启。

## 配置

插件页 → 峰谷教练模式 → 插件配置。也可以直接写进 profile 的 `cordis.patch.yml`：

```yaml
- id: peak-coach
  config:
    enabled: true
    peaks: ['09:00-12:00', '14:00-18:00']
    weekendValley: true
    holidays: ['2027-01-01', '2027-02-06']
    unlockedMinutes: 10
```

| 字段 | 默认 | 说明 |
|---|---|---|
| `enabled` | `true` | 总开关。关掉＝任何时段都是默认模式 |
| `peaks` | `['09:00-12:00','14:00-18:00']` | 高峰窗口，北京时间，支持跨零点写法 |
| `weekendValley` | `true` | 周末全天算谷时。别关，关了周末反而被拦 |
| `holidays` | `[]` | 额外的谷价日期，`YYYY-MM-DD`。每年国务院公布次年安排后自己补 |
| `blocked` | 见下 | 峰时且**没有用户指令**时要拦的工具（有指令时一律放行） |
| `unlockedMinutes` | `10` | `peak_unlock` 一次解锁多久 |
| `coachText` | 空 | 留空用内置教练文案；填了就用你的 |

默认拦截：`write` `edit` `pwsh` `bash` `shell` `subagent` `subagent_fork` `workflow` `plugin_manager` `purge_apply` `purge_revert` `schedule_create` `schedule_edit` `create_goal` `update_goal` `bili_run` `bili_reply` `pixiv_save`。

## 为什么用 guard 而不是提示词

提示词是劝。模型可能不理你，照样调 `write`。

`ctx.tools.guard()` 是工具层的单调拒绝：调用一到就被挡，理由作为工具结果回给模型，它只能改口给方案。而且 guard 每次调用都重新判定时段，所以跨过 18:00 不需要重启，下一句就自动切换。

## 卡住了怎么出来

guard 是真拒绝，所以它把**模型自己也拦住了** —— 模型想改自己的配置、想关插件都做不到。峰时窗口配错（比如手滑写成全天）就会卡死，而出口在工具层之外。留了两个不经过工具层的开关：

1. 环境变量 `DSH_PEAK_COACH_OFF=1`
2. 建一个空文件 `~/.dsh/peak-coach.off`（有 `DSH_HOME` 就在那下面）

任何一个成立，闸门立刻放行。文件每 1 秒最多检查一次，建了 1 秒内生效，删掉也 1 秒恢复。

删掉文件：

```powershell
Remove-Item "$env:USERPROFILE\.dsh\peak-coach.off"
```

## 已知边界

- `peak_unlock` 的放行窗口是**进程级**的，不按会话隔离。单用户单机没问题；一台机器上多个会话同时跑时，一个会话解锁，其它会话也短暂放行。
- 时段判定用的是本机时钟 + 固定 UTC+8，不看系统时区设置。机器时间不准，判定就不准。
- 法定节假日清单要自己维护 —— 官方按国务院安排走，插件不联网拉。
- 它不改变上游计费，只改变「这一轮干了多少活」。峰时你硬要它干，钱还是照付。
